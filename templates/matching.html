How Mealprint Matches Ingredients

Technical White Paper · Version 1.0 · March 2025

Every recipe added to Mealprint contains free-text ingredient lines — things like "1 cup finely chopped onion" or "2 large eggs, beaten". Before a CO2 value can be calculated, each line must be translated into a specific entry in our climate database with a known weight in grams.

This document explains exactly how that translation works, what approximations are made, and where the limits of the system lie. It covers five topics:

  1. 1. The matching pipeline — the five steps from raw text to a CO2 value
  2. 2. Ingredient aliases — curated mappings from recipe terms to database names
  3. 3. Piece weights — standard gram values for countable ingredients
  4. 4. Density categories — converting volume measurements to grams
  5. 5. Limitations — where approximations are made and what can't yet be matched

1. The Matching Pipeline

Each ingredient line goes through five steps in sequence before a CO2 value is assigned.

  1. 1

    NLP Parse

    We use ingredient-parser-nlp, a CRF model trained on 81,000 annotated ingredient sentences. It extracts the amount, unit, and clean ingredient name — stripping prep notes like "finely chopped", "diced", or "to taste". For example, "1 cup finely chopped onion" becomes amount=1, unit=cup, name=onion.

  2. 2

    Informal Unit Preprocessing

    Informal units that aren't in the standard unit conversion table are normalised before matching: handful → 30g, pinch → 0.5g, dash → 0.5g, sprig → fixed piece weight. Unitless piece-based ingredients (e.g. "2 eggs", "3 garlic cloves") are detected and routed to the piece weight lookup in step 2 of weight conversion.

  3. 3

    Alias Lookup

    The parsed name is checked against a curated alias dictionary using longest-match substring logic. This maps everyday recipe terms to the canonical names used in the climate database — for example, heavy cream → Cream, whipping, 38% fat, or all-purpose flour → Wheat flour, type 55. The full list is in the aliases table below.

  4. 4

    Hybrid Fuzzy Matching

    The name is scored against all ~2,957 entries in the climate database using two signals in parallel: a token word overlap score and a rapidfuzz WRatio fuzzy string score. A match is accepted when the word score is ≥ 4 and the fuzzy score is ≥ 92%. Both thresholds must pass.

  5. 5

    AI Fallback (Mistral)

    When confidence falls below the threshold, the ingredient is sent to Mistral AI, which selects the best match from the full database. This handles unusual or compound ingredient names that trip up string-based matching. Each ingredient stores a matched_by value recording which step produced the match.

Database priority: Matches are searched in The Big Climate Database (Danish, ~500 ingredients, CO2 + nutrition) first, then Agribalyse (French, ~2,500 ingredients, CO2 only) as a fallback.

5. Limitations

  • • Proxy matches: Some ingredients have no close entry in the database. We use the nearest reasonable proxy — for example, dried tarragon is matched to oregano (dried), and Manchego to a generic hard cow's milk cheese. These approximations are visible in the alias table above.
  • • Can weights: Canned ingredients default to 400g net weight. Exceptions: tuna (150g), sardines (100g), anchovies (50g).
  • • Piece weights: Population averages are used. A large egg weighs more than a small one; garlic clove sizes vary by variety. These are best-estimate values, not measurements.
  • • Database coverage: ~2,957 ingredients are currently indexed. Novel, branded, or highly processed ingredients may fall back to a proxy or remain unmatched and require manual review in the admin panel.
